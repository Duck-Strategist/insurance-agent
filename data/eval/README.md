# 评测集

JSONL，一行一题。格式见 `backend/app/eval/dataset.py` 的 `RetrievalItem`。

| 文件 | 题数 | 来源 |
|---|---|---|
| `retrieval_generated.jsonl` | 166 | LLM 按章节生成 + 人工审核（spec D19、D35） |
| `retrieval_hard.jsonl` | 34 | 手写：口语化、同义改写、跨章节（标签见 `tags`） |

## 字段

- `file_name`：题目针对的条款。评测默认只在这份条款里检索（对话中由代码先定位产品）。
- `gold`：标准章节路径，可以有多个（答案分散在几处，或正文和释义里都有），检索到任一个即命中。
  用章节路径而不是块 id：重新入库后块 id 会变（spec D34）。跑评测前会校验每个路径在库里存在。
- `evidence`：生成题里 LLM 给出的原文依据，已校验逐字出现在标准章节里（忽略空白和表格标签）。
- `note`：审核备注。

## 生成集的构建过程（2026-11-21）

1. `uv run python -m app.eval generate --per-doc 18`：10 份条款各按章节顺序等距抽 18 个章节（正文 ≥ 60 字），
   共 178 个；qwen-plus 每个章节出一题并给出原文依据。依据不在章节里的丢弃（5 题），得到 173 题草稿。
2. 人工审核删除 7 题：
   - gen-001 阅读指引里的指向语，答案在别的章节；
   - gen-053 条款目录残留（结构问题，spec Q13）；
   - gen-069 附表病种列表，答案在轻度疾病定义里，标准不唯一；
   - gen-070 / gen-088 / gen-106 / gen-159 问公司名、条款全称、条款结构的元问题，不是用户会问的。
3. 4 题（gen-082/100/115/122）的标准章节路径不准：长病种标题没被识别，正文挂在了上一个病种下（spec Q13）。
   按正文在库里实际所在的章节标注，并写了 `note`。

## 修改评测集时

- 改动后文件哈希会变，`eval_runs.dataset_hash` 不同的结果不能直接比较。
- 结构规则改动导致章节路径变化时，评测会报「标准章节在库里不存在」；路径还在但原文依据已不在该章节时，会报「原文依据已不在标准章节里」（spec D40）。生成题按依据重新标注，不要只按路径。

## 路由与端到端评测集（M8）

| 文件 | 题数 | 用途 |
|---|---|---|
| `routing_test.jsonl` | 203（多轮 55） | 路由测试集，只用来报告（spec D56） |
| `routing_dev.jsonl` | 51（多轮 8） | 路由开发集，调提示词时只看它；与测试集不重题（有单测检查） |
| `e2e_clause.jsonl` | 86 | 端到端：生成集每份条款等距取 4 题（40）+ 难题集全部（34）+ 手写无答案题（12） |

路由题字段：`intent` 标准意图；`products` 路由后应得到的产品（名称，跑评测时校验都在产品目录里），追问时按路由层语义沿用上一轮产品；
`history` 之前的对话；`last_workflow` / `last_products` 上一轮的业务和产品；`tags` 如 多轮、只回产品名、跨业务、边界。

端到端题不写参考答案：裁判对照 `gold` 章节在库里的原文（和生成题的 `evidence`）打分（spec D57）。无答案题（`answerable: false`）
在入库的全部条款里搜过关键词，确认条款没有答案；「保费能用信用卡分 12 期吗」是有意的陷阱：条款里的「分期支付保险费」指按年交。
