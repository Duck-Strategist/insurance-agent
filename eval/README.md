## 检索 v1（M3，2026-11-21）

- 范围：只在题目对应的条款内检索（对话里由代码先定位产品）。
- 命中：返回的前 k 个章节（父块）里有任一标准章节。延迟单位毫秒，本节数字 = 向量化 + 召回 + 重排；
  之后的运行改为向量化 + 检索墙钟时间，多算了取章节原文的一次查询（实测约 10 ms，记为 `load_ms`）。
- 向量 text-embedding-v4（1024 维）；基线重排 gte-rerank-v2（之后对比了 qwen3-rerank，见下）；每路召回 30 个子块，RRF k=60，重排 30 个候选，返回 5 个章节。
- 完整报告（含未命中题目列表）：[reports/retrieval-document-20261121-185832.md](reports/retrieval-document-20261121-185832.md)

### 结论

1. **生成集测不出差别**：问题和原文的最长公共子串中位数 6 字（难题集 2 字），三种配置 R@5 都在 0.98 以上。
   只看生成集会以为检索已经做完了（spec Q8）。
2. **重排是主要收益，且重排模型的选择影响很大**：生成集 R@1 0.82 → 0.96–0.97；难题集上 gte-rerank-v2 只把 MRR 从 0.59 提到 0.62，qwen3-rerank 提到 0.82。代价是 P50 多 1.0–1.7 秒。
3. **全文召回在口语题上是噪声**：不重排时，混合在难题集上比纯向量差（R@1 0.47 → 0.24）；降低全文权重能缓解，
   但仍不如纯向量。重排后权重对结果几乎没有影响（差异不超过 1 题）。线上默认「混合 + 重排（qwen3-rerank）」、权重 1.0（spec D33）。
4. **剩下的错题是词汇鸿沟**：gte-rerank-v2 下难题集 7 题未进前 5，换 qwen3-rerank 后剩 3 题（既往症、等待期、心梗↔疾病免责），
   调检索参数解决不了，留给 M4 的查询改写（spec Q14）。
5. 附表表格（spec Q11）未观察到对召回的影响；评测集审核发现的结构问题记在 spec Q13。

## 查询改写（M4，2026-11-21）

`--rewrite`：先用对话模型（qwen-plus）把问题改写再检索；`--keep-original`：原问题也一起召回、用改写结果重排。
配置均为「混合 + 重排（qwen3-rerank）」，范围 document。改写本身的耗时（约 1–2 秒）不在表里的延迟中。

| 改写方式 | 生成集 R@1 / R@5 / MRR | 难题集 R@1 / R@5 / MRR | 运行 |
|---|---|---|---|
| 不改写（基线） | **.964 / 1.000 / .980** | **.735** / .912 / **.818** | #21 / #22 |
| 换术语，提示词示例取自难题集错题（泄漏） | .916 / .994 / .949 | .794 / .941 / .858 | #39 / #41 |
| 同上 + 原问题一起召回（泄漏） | .928 / 1.000 / .959 | .824 / .971 / .878 | #43 / #45 |
| 换术语，示例不取自评测集 | .934 / .994 / .962 | .676 / .941 / .785 | #46 / #47 |
| 同上 + 原问题一起召回 | .934 / .994 / .963 | .676 / .912 / .784 | #48 / #49 |

结论：

1. **泄漏**：第一版改写提示词里的「口语→术语」示例，是照着难题集的错题写的（免赔额、既往症、等待期、减保……）。
   它在难题集上「涨」到 R@5 0.971，去掉这些示例后只有 0.912，和不改写一样，R@1、MRR 还更低（spec Q16）。
2. **换术语的改写没有用**：两个集上都不如直接用原问题检索，还多一次 LLM 调用。
   改写会丢掉原问题里与条款原文一致的措辞；而 qwen3-rerank 本身已经能处理一部分口语。
3. 线上因此只用改写补全指代（「那它」「那生孩子呢」），不换术语；第一句不改写；
   改写结果与原问题一起召回（spec D39）。评测集里的题都是独立问题，线上对这些题的检索等同于基线 #21 / #22。
